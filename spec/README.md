# spec/

Your answers, written down. One file per module.

These files are the contract between the interview and the build prompt. The
build prompts in `src/*/PROMPT.md` read them - that is the whole reason they
exist. A build prompt with no spec has to ask you everything again, or guess.

Nothing here is generated automatically. Run `/harness-interview` and the agent
writes them from your answers. Edit them by hand any time; they are yours.

Commit them. When someone asks in six months why the harness refuses to push to
git, the answer is in `guardrails.md`, in your own words.

`example/` holds one filled-in spec so you can see the target before you have
answered anything. Delete it when it stops being useful.
